# OnStar — إعادة بناء الواجهة (إصدار مستقل)

نسخة جديدة لواجهة **OnStar App + OnStar Cloud**، مبنية من الصفر خارج ملفات التصميم السابقة. يحتوي هذا المشروع على الواجهة الأمامية فقط، ومحتوى المشروع القديم وأصوله العامة، وتعليمات نشر Netlify. **لا يحتوي على Backend أو قاعدة بيانات أو ملفات اعتماد.**

## المخرجات الأساسية

- صفحة رئيسية تتضمن مشهدًا تقنيًا توضيحيًا وتبديلًا تفاعليًا بين المنتجين.
- صفحة منتج تطبيق Android، مع صور حقيقية من الملفات المرفقة و11 تصنيفًا للأدوات.
- صفحة خدمة OnStar Cloud مع مسار الاشتراك ومعلومات الأجهزة المدعومة.
- بوابة العميل بتبويبات (نظرة عامة، باقات، فواتير، تجربة، MikroTik، الوصول، أجهزة، أمان)، متصلة بمسارات API الحالية دون افتراض نتائج.
- مركز معرفة يقرأ **128 أداة، و35 رابط فيديو أصلي، و36 دليلًا** من مصادر البيانات الأصلية. يوجد بحث فوري وفلاتر وروابط تفصيلية قابلة للمشاركة.
- إعادة توجيه المسارات القديمة المتوافقة (`/features`, `/guide`, `/tutorials`, `/remote-access` وغيرها) ضمن تطبيق الواجهة.
- RTL واستجابة للشاشات الصغيرة ودعم `prefers-reduced-motion`.

## المتطلبات

- Node.js 20 أو أحدث. لا يلزم تثبيت أي مكتبات خارجية أو تشغيل `npm install`.
- للنشر في Netlify: اربط المستودع بالمشروع واستخدم إعدادات `netlify.toml` المرفقة.

## التشغيل محليًا

```bash
npm run dev
```

افتح `http://localhost:4173`. جميع الصفحات والمحتوى تعمل محليًا، لكن **وظائف الحساب لا تعمل محليًا** عبر خادم المعاينة المرفق: يرد `/api/customer/*` برمز 503 توضيحيًا بدل إرسال الطلبات إلى الإنتاج، لحماية حسابات العملاء من أي اختبار غير مقصود. للاختبار التكاملي استخدم Netlify deploy preview مع حساب اختبار مفوض وبعد التحقق من إعدادات Proxy/Cookie.

## البناء للنشر

```bash
npm run check
npm run build
```

يمكن رفع مجلد `dist` في Netlify، بشرط إبقاء `netlify.toml` في المصدر المرتبط بالنشر حتى يطبّق Netlify إعادة التوجيه. الخيار الأفضل هو ربط مستودع المشروع واستخدام `npm run build` مع Publish directory = `dist`، عندها تُقرأ قواعد Proxy من الملف المصدر. **رفع مجلد dist يدويًا فقط قد لا يطبّق `netlify.toml` الموجود خارجه**؛ عند النشر اليدوي انقل قواعد النشر إلى إعدادات Netlify أو وفّر `_redirects` المناسب بعد اختبار الجلسات.

## الأمان والتكامل

- مسار الواجهة إلى الخدمة: `/api/customer/*`، والوجهة الأصلية في `netlify.toml` كما كانت في المشروع المرفق.
- الجلسة تعتمد على HttpOnly Cookie من الخدمة؛ الطلبات تستخدم `credentials: include`.
- بيانات العميل تُجلب من `/me` والواجهات المرتبطة؛ لا توجد بيانات مالية وهمية أو بطاقات اشتراك ثابتة.
- لا توضع كلمات مرور أو مفاتيح جلسات في `localStorage`.
- إرسال إثبات الدفع وطلب التجربة هما طلبا مراجعة، لا تفعيل نهائيًا.
- استخدم بيئة اختبار مفوضة قبل توجيه النطاق الإنتاجي إلى هذه النسخة. لا تُجرِ اختبارات مالية فعلية أو تعديلات على أجهزة العملاء.

## خارطة الملفات

```text
index.html                  نقطة دخول التطبيق
src/main.js                 توجيه الصفحات وتفعيل التفاعل
src/api.js                  Client API مع JSON/FormData ومعالجة الأخطاء
src/components/layout.js    الهيدر، الفوتر والإطار الموحد
src/pages/marketing.js      الرئيسية وصفحات المنتجات والخدمات
src/pages/knowledge.js      البحث، التصنيفات والأدلة والفيديوهات
src/pages/auth.js           التسجيل والمصادقة والتأكيد والاستعادة
src/pages/account.js        لوحة العميل وجميع إجراءات الاشتراك
src/styles/style.css        Design Tokens + CSS الأصلي الجديد + Responsive
public/content/             ملفات المحتوى الأصلية بعد التحويل إلى JSON صالح للقراءة
public/app-assets, media/   صور وأصول أصلية من ZIP
scripts/                    بناء بدون مكتبات واختبارات ثابتة ومحاكاة
reports/                    تقرير التكامل والتوافق
netlify.toml                قواعد النشر وReverse Proxy
```

## ملاحظات التسليم الصريحة

هذه نسخة frontend قابلة للبناء والنشر، وليست تأكيدًا لصحة جميع الوظائف على **السيرفر الإنتاجي**. لم تُختبر عمليات الدفع والتجربة وVPN مباشرة على الإنتاج. لم تُنجز مراجعة بصرية كاملة عبر متصفح آلي لأن تشغيل Chromium headless في بيئة البناء تعثر؛ لذلك ينبغي إجراء اختبار بصري على الهاتف والكمبيوتر قبل استبدال الموقع الحالي. كذلك لم تُنفذ واجهة إدارة داخلية منفصلة، لأن الطلب قصر العمل على واجهة الموقع وبوابة العميل مع الربط بلوحة الأجهزة الحالية.

**خيار هندسي:** استُخدمت JavaScript ES Modules أصلية، بدلاً من React/Vite، للحفاظ على مشروع خفيف بدون حزم خارجية في بيئة لا تتيح تنزيل الاعتماديات. هذا يختلف عن المكدس المقترح الاختياري، مع الحفاظ على فصل الوحدات والوظائف. إذا كانت React/TypeScript إلزامية للفريق، ستلزم ترحيل طبقة العرض قبل اعتماد المشروع كنسخة نهائية بذلك المكدس.
